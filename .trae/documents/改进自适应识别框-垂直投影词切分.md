# 改进自适应识别框：垂直投影词切分

## 总结

参考 SnapTraTranslator（Swift）的三层"自适应识别框"分析，对本项目 QuickTranslate 逐层对照后确认：

| 层次 | 参考项目做法 | 本项目现状 | 结论 |
|------|-------------|-----------|------|
| 第1层 截屏区域 | 光标为中心固定窗口 + 屏幕交集防越界 | `GdiScreenCapture.CaptureAroundAsync`（720×320 光标跟随 + `ClampRegionToBounds`） | **已达标，不改** |
| 第2层 词边界框 | 三策略递进：精确框 → 字符比例法 → CoreText 字宽 | 仅"字符比例法"（`BuildWords`，CJK占2单位/拉丁占1单位平分行宽） | **主要差距，本次改进** |
| 第3层 选词命中 | 严格命中 → 容差放宽 → 中心距离最近 | `WordSelector`：Contains → 面积最小 → 中心距离；动态 `MaxAnchorDistance` | **已达标，不改** |

**根因**：PP-OCRv6 Recognizer（CTC 解码）只输出整行文本 + 行框。`PaddleOcrV6Engine.BuildWords`（861-938 行）按"字符单位数平分行宽"生成词框，假设所有拉丁字符等宽。比例字体下 "iii" 与 "www"、"go" 与 "translation" 实际渲染宽度差异巨大，导致框不贴合词长——即用户报告的"选词框不准确、不自适应词长"。

**方案**：实现项目 spec 8.3 规划但未落地的**垂直投影词切分**（等价于参考项目的"策略① 精确框"）：对行裁剪位图做列墨水投影，按空白间隔切出每个词的真实像素边界。段数与 token 数一致时采用精确框；不一致（CJK 混排、噪声等）时回退现有加权比例法（参考项目标注"最稳定的方法"作兜底，哲学一致：稳优先）。

## 改动方案

### 1. 新增 `src/QuickTranslate.Core/Ocr/ProjectionWordSegmenter.cs`

静态类，方法签名：

```csharp
public static bool TrySegment(
    Bitmap lineBitmap,        // recSource：送入 Recognizer 的行位图（局部坐标）
    string recognizedText,    // RunRecognizer 输出的整行文本
    PhysicalRect localBox,    // det 框（frame.Bitmap 局部坐标）
    PhysicalRect frameRegion, // 截屏区域（屏幕绝对坐标）
    bool rotated180,          // clsNeedRotate：recSource 是否经过 Rotate180
    int lineIndex,
    out IReadOnlyList<OcrWord> words)
```

算法（对应参考项目"策略① + 校验回退"）：

1. **二值化**（LockBits 灰度）：阈值 = 灰度均值 × 0.6；统计暗像素占比，若 > 0.5 判定为暗色主题（暗底亮字），反转极性。
2. **列投影**：`colInk[x]` = 该列前景像素数；`colInk[x] < max(1, H × 0.02)` 视为空列（抑制孤立噪点）。
3. **找 gap**：连续空列区间宽度 ≥ `max(2, round(H × 0.16))`（词间距经验值 ≈ 0.25 × 字号 ≈ 0.16 × 行框高）视为词分隔。
4. **提取墨水段**：相邻 gap 之间的 `[xStart, xEnd]` 区间，段宽 ≥ 2px。
5. **对齐校验**（对应参考 `isValidTokenBoundingBox` 思路）：`tokens = recognizedText.Split(' ', RemoveEmptyEntries)`；仅当 `段数 == token 数` 且 token 均非空时，段与 token 按从左到右顺序一一映射。
6. **坐标换算**（位图局部 → 屏幕绝对）：
   - 若 `rotated180`：`x_orig = W - x_rot`（180° 旋转把矫正图的 X 翻回原 det 框坐标）
   - `screenX = frameRegion.X + localBox.X + x_orig`
   - 词框 Y/Height 沿用行框（`screenBox.Y/Height`）
7. 任一校验不过（段数不匹配、纯 CJK 行无 gap、空图像）→ 返回 `false`，由调用方回退。

词框置信度取 0.9（与现有 `BuildWords` 英文词一致）。

### 2. 修改 `src/QuickTranslate.Infrastructure/Ocr/PaddleOcrV6Engine.cs`（约 322-328 行）

```csharp
if (!string.IsNullOrWhiteSpace(recText))
{
    // 优先垂直投影精确词框（spec 8.3：空白间隔/垂直投影）；失败回退加权比例法
    IReadOnlyList<OcrWord> words;
    if (!ProjectionWordSegmenter.TrySegment(recSource, recText, box, frame.Region, clsNeedRotate, lineIdx, out var projWords))
    {
        words = BuildWords(recText, screenBox, lineIdx);
        _logger.LogDebug("WordBox: fallback=proportional tokens={Tokens} line={Idx}", recText.Split(' ').Length, lineIdx);
    }
    else
    {
        words = projWords;
        _logger.LogDebug("WordBox: fallback=none projection tokens={Tokens} line={Idx}", projWords.Count, lineIdx);
    }
    var ocrLine = new OcrLine(screenBox, words, recText, clsAngle);
    lines.Add(ocrLine);
}
```

### 3. 新增测试 `tests/QuickTranslate.Tests/Core/ProjectionWordSegmenterTests.cs`

用 GDI+ `Graphics.DrawString` 绘制已知文本生成位图（测试项目已在多处使用 `System.Drawing`）：

1. **不同词长自适应**（核心回归）：绘制 `"go translation important"`（Arial，白底黑字）→ 3 段；断言 translation 段宽 / go 段宽 > 3（比例法下约 11/2 vs 实际渲染差异更悬殊；宽松阈值防字体渲染差异）。
2. **两词切分与坐标**：`"Hello World"` → 2 段，两框互不重叠、均落在行框内、左词对应 "Hello"。
3. **暗色主题**：黑底白字同样正确切分（极性反转）。
4. **无空格单词**：`"HelloWorld"` → 1 段 1 token，成功。
5. **段数不匹配回退**：文本 `"A B C"` 但图像只有一个墨块 → 返回 `false`。
6. **空图像** → 返回 `false`。
7. **180° 旋转映射**：绘制 `"A BBBBB"` 后手动旋转位图 180°，`rotated180=true` 切分后断言 "A" 的词框 X 小于 "BBBBB" 的词框 X（坐标正确翻回原坐标系）。
8. **噪点抑制**：词间空白处撒 1-2 个前景像素 → 仍正确切分。

### 4. 不改动的部分（明确决策）

- **第1层截屏**：720×320 光标跟随 + clamp 已与参考一致。
- **第3层命中**：`Contains → 距离最近 → 面积/中心 tie-break` 已与参考一致，且有 Case1-12 测试锁定行为。
- **`DefaultWordBoxResolver`**：Words 非空时透传，不受影响。
- **不实现"字宽测量第三策略"**（等价 CoreText）：段数不匹配时直接回退比例法。比例法即参考项目标注"最稳定"的策略②，CJK 混排等边缘场景下足够；避免过度工程。后续若真实样本证明需要，再增加 token-段贪心对齐。

## 假设与决策

- **垂直投影 = 本项目的"精确框"**：PP-OCR CTC 无字符级位置输出（Vision 的 `boundingBox(for:)` 无等价 API），从行图像像素直接提取词边界是唯一精确来源，spec 8.3 也正是如此规划（"空白间隔/垂直投影"优先于"字符区间估计"）。
- **gap 阈值 0.16 × 行高**：词间空格 ≈ 0.25 × 字号 ≈ 0.2 × DB 框高，取 0.16 留安全余量，避免字距大的字体被误切。
- **`rotated180` 映射**：Rotate180 后识别文本阅读顺序与投影段从左到右一致（180° 矫正使颠倒行恢复正常顺序），仅需 X 翻转回原 det 框坐标。
- **性能**：典型行 400×30 像素 LockBits 遍历，微秒级，不影响 OCR 耗时。
